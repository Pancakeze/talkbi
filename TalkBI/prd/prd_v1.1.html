一、需求背景

现状痛点：在交通管理行业，业务人员日常需要进行大量的数据分析工作。但由于他们不懂技术，无法直接操作数据库。目前的流程是：业务人员提需求 -> 技术人员连接数据源 -> 创建数据模型/数据集 -> 生成图表。这个流程链路长、沟通成本高、响应速度慢，导致业务人员无法实现“所想即所得”的自助式分析。

为什么现在做：随着大语言模型（LLM）技术的发展，通过自然语言转化为 SQL 并生成图表（Text-to-SQL/Chart）的技术已经成熟。我们需要一款对标 FineBI/DataEase 企业级严谨性，但交互门槛极低的产品，释放技术团队压力，赋能业务人员。

二、需求目标

目标类型 描述 衡量指标 目标值
用户体验 降低业务人员获取数据图表的门槛 业务人员独立生成图表的平均耗时 从“天”级缩短至“分钟”级
业务效率 减少技术团队在基础数据提取上的工作量 技术团队接到的常规取数需求数量 下降 70%
系统能力 提供安全、灵活的对话式分析能力 支持的数据源类型及私有化模型响应成功率 支持5+种数据源，SQL生成准确率>85%

三、用户与使用场景

3.1 核心用户角色

  • 业务人员（主要使用者）：不懂 SQL，熟悉交通管理业务指标。需要快速查看数据趋势、生成报告。
  • 系统管理员/技术人员（支撑者）：负责配置数据源（MySQL, Doris, PgSQL, Oracle 等），划分主题库，处理 AI 无法解决的复杂异常查询。

3.2 核心用户旅程 (User Journey Map)

阶段 用户触点 用户行为 痛点/情绪 产品机会点 (TalkBI 解决方案)
1. 准备阶段 首页/主题库列表 选择需要分析的“主题库”（如：交通流量主题、违章记录主题），或上传 Excel 补充数据 不知道去哪里找数据 (😐) 管理员预置主题库，用户只需做单选题；支持 Excel 联合查询，打破数据孤岛。
2. 探索阶段 对话框界面 输入自然语言（例：“帮我统计上个月各个路口的拥堵指数”），与 AI 交互 不知道怎么描述需求，怕 AI 听不懂 (😟) AI 在主题库范围内自动决策查哪些表；提供示例提问引导。
3. 结果验证 图表展示区 查看 AI 生成的图表和底层数据逻辑 生成的图表类型不是我想要的，或者颜色不好看 (🤔) 提供“视觉层”和“数据逻辑层”的双重二次编辑能力，所见即所得。
4. 沉淀分享 图表库/仪表盘 将满意的图表保存到个人文件夹，分享给同事，或组装成仪表盘 做完的图表下次找不到了，无法给领导汇报 (😞) 建立个人图表库，支持分享链接，支持多图表拼接为 Dashboard。

五、详细方案

功能 1：对话式图表生成 (核心链路)

交互流程图

flowchart TD A[选择主题库] --> B[输入自然语言] B --> C[AI解析并生成SQL] C --> D[执行查询] D --> E[渲染图表] E --> F[展示执行逻辑(维度/度量)]

规则描述

  • 触发条件: 用户在左侧对话框输入文字并发送。
  • 交互反馈: 发送后展示 loading 状态（"正在分析数据模型并生成图表..."）。成功后展示 AI 总结文案、执行逻辑卡片，并提供“在右侧预览图表”按钮。
  • 前置校验: 必须先选择顶部的主题库（下拉菜单）。
🔍 专注模式沙盒：对话交互区 (业务端)

功能 2：图表二次编辑 (视觉与数据逻辑)

交互流程图

flowchart TD A[图表生成完毕] --> B{编辑类型} B -->|视觉编辑| C[顶部工具栏] C --> D[切换柱/折/饼图等] B -->|逻辑编辑| E[底部抽屉面板] E --> F[增删改维度/度量/条件] F --> G[重新触发查询渲染]

规则描述

  • 视觉编辑: 右侧图表区顶部提供快捷工具栏，支持一键切换图表类型、导出图片、保存图表。
  • 逻辑编辑: 底部“数据逻辑编辑”面板展示当前图表的 X轴(维度)、Y轴(度量)和筛选条件。用户可删除或修改，修改后实时刷新图表。
  • 标题编辑: 鼠标悬停图表标题可直接进行内联编辑。
🔍 专注模式沙盒：图表编辑区 (业务端)

v1.1 新增 功能 3：图表库拖拽至仪表盘

交互流程图

flowchart TD A[进入图表库] --> B[长按图表卡片] B --> C[拖拽至仪表盘菜单或画布] C --> D[释放鼠标(Drop)] D --> E[仪表盘自动增加新图表块] E --> F[开启编辑模式调整大小/位置]

规则描述

  • 拖拽源: 在“个人图表库”中，所有的图表卡片都可以被鼠标长按并拖拽（HTML5 Drag and Drop API）。
  • 放置目标: 拖拽到左侧菜单的“仪表盘”入口，或直接在仪表盘画布上释放。
  • 布局调整: 仪表盘支持“编辑布局”模式，允许用户调整各个图表卡片的栅格占比（如占据 1列 或 2列）。
🔍 专注模式沙盒：图表拖拽交互 (业务端)

v1.1 新增 功能 4：管理员视图与异常流转

交互流程图

flowchart TD A[业务人员AI报错] --> B[点击'联系管理员'] B --> C[生成后台工单] C --> D[管理员登录进入后台] D --> E[查看'AI异常求助工单'] E --> F[查看原始问题与SQL报错日志] F --> G[修改主题库配置或数据字典]

规则描述

  • 角色切换: 系统根据登录账号权限，展示不同的左侧菜单（业务人员菜单 vs 管理员菜单）。
  • 主题库配置: 管理员可以将多张物理表打包成一个“主题库”，供业务人员选择。
  • 工单处理: 当业务人员遇到 AI 无法解析的查询时，提交的工单会流转到管理员的“运维中心”。管理员可以看到用户的原话和底层的真实报错日志（如：找不到列名），从而针对性地修复数据模型。
🔍 专注模式沙盒：管理员后台视图

七、异常与边界处理

  • 数据权限越界：AI 生成的 SQL 只能在用户当前选定的“主题库”范围内执行，禁止跨库/跨主题查询未授权表。
  • Excel 联合查询性能：对于用户上传的极大 Excel 文件，需限制文件大小（如 50MB），并在后台进行临时表构建以保证查询性能。
  • 并发查询限制：为防止拖垮业务库，对同一用户的并发查询数需做限制（如最多同时执行 2 个图表查询）。
