一、需求背景

现状痛点：在交通管理行业，业务人员日常需要进行大量的数据分析工作。但由于他们不懂技术，无法直接操作数据库。目前的流程是：业务人员提需求 -> 技术人员连接数据源 -> 创建数据模型/数据集 -> 生成图表。这个流程链路长、沟通成本高、响应速度慢，导致业务人员无法实现“所想即所得”的自助式分析。

为什么现在做：随着大语言模型（LLM）技术的发展，通过自然语言转化为 SQL 并生成图表（Text-to-SQL/Chart）的技术已经成熟。我们需要一款对标 FineBI/DataEase 企业级严谨性，但交互门槛极低的产品，释放技术团队压力，赋能业务人员。

二、需求目标

目标类型 描述 衡量指标 目标值
用户体验 降低业务人员获取数据图表的门槛 业务人员独立生成图表的平均耗时 从“天”级缩短至“分钟”级
业务效率 减少技术团队在基础数据提取上的工作量 技术团队接到的常规取数需求数量 下降 70%
系统能力 提供安全、灵活的对话式分析能力 支持的数据源类型及私有化模型响应成功率 支持5+种数据源，SQL生成准确率>85%

三、用户与使用场景

3.1 核心用户角色

  • 业务人员（主要使用者）：不懂 SQL，熟悉交通管理业务指标。需要快速查看数据趋势、生成报告。
  • 系统管理员/技术人员（支撑者）：负责配置数据源（MySQL, Doris, PgSQL, Oracle, Excel 等），划分主题库，处理 AI 无法解决的复杂异常查询。

3.2 核心用户旅程 (User Journey Map)

阶段 用户触点 用户行为 痛点/情绪 产品机会点 (TalkBI 解决方案)
1. 准备阶段 首页/主题库列表 选择需要分析的“主题库”（如：交通流量主题、违章记录主题） 不知道去哪里找数据 (😐) 管理员预置主题库，用户只需做单选题；支持跨主题联合查询。
2. 探索阶段 对话框界面 输入自然语言（例：“帮我统计上个月各个路口的拥堵指数”），与 AI 交互 不知道怎么描述需求，怕 AI 听不懂 (😟) AI 在主题库范围内自动决策查哪些表；提供示例提问引导。
3. 结果验证 图表展示区 查看 AI 生成的图表和底层数据逻辑 生成的图表类型不是我想要的，或者颜色不好看 (🤔) 提供“视觉层”和“数据逻辑层”的双重二次编辑能力，所见即所得。
4. 沉淀分享 图表库/仪表盘 将满意的图表保存到个人文件夹，分享给同事，或组装成仪表盘 做完的图表下次找不到了，无法给领导汇报 (😞) 建立个人图表库，支持分享链接，支持多图表拼接为 Dashboard。

五、详细方案

功能 1：多主题库联合分析 (跨库查询)

交互流程图

flowchart TD A[点击顶部主题库下拉框] --> B[勾选多个主题库] B --> C[如: 交通流量 + 违章事故] C --> D[输入跨主题问题] D --> E[AI识别关联字段(如:行政区)] E --> F[生成包含 JOIN 的 SQL] F --> G[渲染散点图等关联图表]

规则描述

  • 多选交互: 顶部的“当前分析范围”改为多选下拉框。用户可以同时勾选多个主题库。
  • 跨主题查询: 当选中多个主题时，AI 会尝试寻找两个主题之间的共同维度（例如“行政区”或“时间”），并生成 `JOIN` 语句。
  • 图表推荐: 对于涉及两个度量（如拥堵指数、事故数量）的跨主题查询，系统优先推荐“散点图”或“双轴折线图”以展示相关性。
🔍 专注模式沙盒：多主题联合分析 (业务端)

v1.3 更新 功能 2：管理员视图 - 数据源管理 (含 Excel)

交互流程图

flowchart TD A[管理员进入'数据源管理'] --> B{选择接入方式} B -->|接入数据库| C[输入IP/账号等信息] B -->|上传 Excel| D[上传本地文件] C --> E[测试并保存] D --> F[后台解析为临时表] E --> G[统一在数据源列表中展示] F --> G

规则描述

  • 统一管理: 无论是物理数据库（MySQL/Doris）还是本地上传的 Excel 文件，都作为平级的数据源在列表中统一管理。
  • Excel 解析: 上传 Excel 后，系统会自动将其解析为一张虚拟的数据表，并展示在列表中。
  • 状态监控: 列表展示各数据源的连接状态、文件大小和最后同步时间。
🔍 专注模式沙盒：数据源管理 (管理员端)

v1.3 更新 功能 3：管理员视图 - 主题库管理(语义层)

交互流程图

flowchart TD A[新建/编辑主题库] --> B[步骤1: 从数据源选表] B --> C[勾选需要的物理表或Excel表] C --> D[步骤2: 字段语义配置] D --> E[为英文字段添加中文别名] E --> F[隐藏不需要的系统字段] F --> G[保存主题库发布]

规则描述

  • 选表逻辑: 主题库是一个虚拟的集合。管理员可以从已连接的数据源（包括 Excel）中，挑选出业务相关的表组成一个主题。
  • 语义映射 (核心): 物理表中的字段往往是英文（如 `status_code`），管理员必须为其配置中文别名（如“设备状态”），这样 AI 才能听懂业务人员的自然语言提问。
  • 字段隐藏: 诸如 `internal_ip` 或 `id` 等技术字段，可以配置为“不可见”，避免干扰 AI 解析。
🔍 专注模式沙盒：主题库选表与语义配置 (管理员端)

七、异常与边界处理

  • 跨主题联合查询失败：如果用户选择了两个毫无关联的主题库（例如“违章记录”和“食堂采购”），AI 无法找到公共维度进行 JOIN，此时应直接提示用户：“这两个主题库之间缺乏关联字段，无法进行联合分析”。
  • 数据权限越界：AI 生成的 SQL 只能在用户当前选定的“主题库”范围内执行，禁止跨库/跨主题查询未授权表。
  • Excel 联合查询性能：对于用户上传的极大 Excel 文件，需限制文件大小（如 50MB），并在后台进行临时表构建以保证查询性能。
